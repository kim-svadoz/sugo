# React 18 하네스 (framework/react/18.x)

`framework/react` 공통 규칙에 더해, React 18의 동시성 모델에서 나오는 제약이다.

## 핵심 규칙

1. **`useEffect`가 두 번 실행돼도 안전하게 쓴다.** 개발 모드 StrictMode는 의도적으로 마운트-언마운트-재마운트를 시뮬레이션한다. 정리(cleanup) 함수로 구독·타이머·요청을 되돌리지 않으면 중복 구독이 쌓이는데, 이건 프로덕션의 진짜 버그를 개발 환경이 미리 드러내 주는 것이다 — StrictMode를 끄는 것으로 "해결"하지 않는다.
2. **`ReactDOM.render`를 쓰지 않는다.** 18에서 폐기됐고 `createRoot`를 써야 동시성 기능이 켜진다. 예전 API로 마운트하면 자동 배칭과 트랜지션이 조용히 동작하지 않는다.
3. **긴 업데이트는 `useTransition`/`useDeferredValue`로 표시한다.** 입력 응답과 무거운 렌더를 구분하지 않으면 타이핑이 끊긴다.
4. **서버 렌더 결과와 첫 클라이언트 렌더가 달라지지 않게 한다.** `Date.now()`, `window`, 랜덤 값을 렌더 중에 쓰면 하이드레이션 불일치가 나고, 18은 이 경우 그 트리를 통째로 다시 그린다.
