# Next.js 하네스 (framework/nextjs)

버전과 무관하게 App Router 기반 Next.js에 항상 적용되는 규칙. 서버와 클라이언트가 한 저장소에
섞여 있다는 점에서 오는 사고가 대부분이다.

## 핵심 규칙

1. **서버 전용 값을 클라이언트 컴포넌트로 넘기지 않는다.** `'use client'` 경계를 넘는 props는 전부 직렬화되어 브라우저로 전송된다 — API 키나 내부 식별자를 서버 컴포넌트에서 props로 내려보내면 그대로 페이지 소스에 실린다. 서버 전용 모듈에는 `import 'server-only'`를 붙여 경계를 컴파일 시점에 강제한다.
2. **`NEXT_PUBLIC_` 접두어의 의미를 지킨다.** 이 접두어가 붙은 환경변수는 번들에 인라인되어 공개된다. 비밀값에 접두어를 붙이는 순간 되돌릴 수 없다(이미 배포된 번들에 박힌다).
3. **`'use client'`를 트리 위쪽에 습관적으로 붙이지 않는다.** 한 번 붙이면 그 아래 전체가 클라이언트 번들로 들어간다. 상호작용이 필요한 잎 컴포넌트에만 붙인다.
4. **Server Action은 공개 HTTP 엔드포인트로 취급한다.** `'use server'` 함수는 클라이언트에서 직접 호출 가능한 진입점이므로, 인자를 신뢰하지 말고 권한 검사와 입력 검증을 함수 안에서 직접 한다.
5. **요청별 데이터를 모듈 스코프에 캐싱하지 않는다.** 서버 모듈의 전역 변수는 요청 간에 공유되어 사용자 A의 데이터가 B에게 보이는 형태로 샌다.
