# Java 하네스 (lang/java)

## 핵심 규칙

1. **`Closeable`/`AutoCloseable` 자원은 반드시 try-with-resources로 해제한다.** 수동 close는 예외 경로에서 누락되기 쉽고, 커넥션/파일 핸들 누수는 운영 중에야 드러난다.
2. **`equals`를 오버라이드하면 `hashCode`도 반드시 함께 오버라이드한다.** 하나만 바꾸면 `HashMap`/`HashSet`에서 조용히(예외 없이) 깨진다 — 가장 늦게 발견되는 버그 유형 중 하나.
3. **컬렉션을 반환하는 메서드는 `null` 대신 빈 컬렉션을 반환한다.** 호출부가 null 체크를 빼먹으면 그 자리에서 NPE.
4. **필요성이 확인된 어노테이션만 추가한다.** 기존 클래스의 어노테이션 구성을 그대로 복제하지 않는다. `@Setter`·`@Getter`·`@ToString`, 생성자와 Jackson 어노테이션은 각각 실제 호출부, 직렬화·역직렬화 계약 또는 프레임워크 요구를 확인하고, 근거가 없으면 추가하지 않는다.
5. **분기를 지우거나 합치는 수정을 하면, diff가 아니라 수정된 메서드 전체를 다시 읽고 남은 조건·변수가 여전히 필요한지 확인한다.**
6. **같은 변수를 확인하고 → 바꾸고 → 다시 확인하는 흐름을 만들지 않는다.** 최종 값은 한 곳에서 정한다.
7. **기존 코드 스타일을 따르더라도, 분기 구조는 지금 요구사항의 판단 개수에 맞춘다.**
8. **메서드 안에서 플래그로 분기해 다른 값을 고른다면, 판단은 호출하는 쪽으로 올리고 갈래마다 이름 있는 메서드로 나눈다.**
