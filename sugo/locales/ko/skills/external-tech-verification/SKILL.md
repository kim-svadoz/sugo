# 외부 기술 검증 규율

## 원칙

- 외부 라이브러리, 프레임워크, API의 동작을 단정하기 전에 외부 문서를 확인한다.
- 특히 부정 주장("이건 X를 지원 안 한다", "그 기능은 없다")이 위험하다. 외부 증거 없이 단정하면
  false-negative로 잘못된 설계를 유도한다. 증거가 없으면 미검증 가정으로 명시하고 진행한다.
- 긍정 주장도 버전에 민감하다. 프로젝트가 실제로 쓰는 버전을 기준으로 확인한다.

## 실전

- code-agent: 라이브러리 API를 쓰기 전에 실제 시그니처와 동작을 확인한다. 추측으로 API를 만들지 않는다.
- review-agent: 보안과 호환성 주장을 외부 증거로 뒷받침한다. 없으면 미검증으로 표기한다.
- 외부 조회용 MCP가 설정돼 있지 않으면 그 사실을 밝히고 미검증으로 진행한다. 있는 척하지 않는다.
